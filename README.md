# OMIX Journal

Editorial knowledge base and lead-generation front end for OMIX Digital Solutions.
React 19 + Vite 8, Tailwind v4 for layout, and a hand-drawn design system
(`src/styles/design-system.css`) for everything visual.

## Commands

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server (no service worker — see below) |
| `npm run build` | Client build → prerender 19 static routes → verify the PWA |
| `npm run preview` | Serve `dist/` — the only place installability can be tested |
| `npm run icons` | Regenerate the app icon set from `scripts/generate-icons.mjs` |
| `npm run og` | Regenerate the 1200×630 share cards into `dist/og/` |
| `npm run verify:pwa` | Assert the manifest, icons and worker actually shipped |
| `npm run lint` | oxlint |

## PWA

The app is installable: standalone display, maskable icons, three app shortcuts
(Quote / Read / Audit) and a Workbox service worker that precaches the shell and
all assets.

Three pieces have to line up, and `npm run build` fails if they do not:

1. **Manifest** — `public/manifest.webmanifest`, a static file. It is *not*
   generated by `vite-plugin-pwa`: under Vite 8/Rolldown that plugin's
   `generateBundle` hook is skipped, so it silently never wrote the manifest
   while still injecting `<link rel="manifest">` into the HTML.
2. **Registration** — `src/lib/pwa.js`. Same reason: the plugin's
   `registerSW.js` helper was never emitted, so the injected `<script
   src="/registerSW.js">` was a 404. `injectRegister: false` and this module
   owns registration, updates and the install prompt.
3. **Worker** — still generated by `vite-plugin-pwa` (Workbox `generateSW`),
   which works. Options live in `vite.config.js`.

`scripts/verify-pwa.mjs` runs at the end of every build and asserts all three,
plus that every manifest icon and share card is really in `dist/`.

### Testing installability

Service workers are disabled in dev on purpose (`devOptions.enabled: false`) —
a worker during development serves stale shells over HMR. Test against a real
build:

```bash
npm run build && npm run preview
```

Chrome fires `beforeinstallprompt` after the worker takes control, so load the
page once, reload, and the install card appears on the home page. On iOS Safari
that event does not exist, so the card shows Add to Home Screen instructions
instead. Dismissing the card is remembered in `localStorage`.

### Share cards

Every public route gets a generated 1200×630 Open Graph card in `dist/og/`,
drawn in the same design system (paper, grain, marker type, ring + exclamation).
`scripts/generate-og.mjs` wraps and sizes each title against the real font
metrics, so a long headline steps down in size instead of overflowing, and
adding an article or category produces its card automatically — a preview can
never go stale or missing. `src/lib/meta.js` maps routes to card paths; the
prerenderer writes the tags as absolute URLs, which is what crawlers require.
Cards are build output, so under `npm run dev` the tags point at files that do
not exist yet — run `npm run build && npm run preview` to see real previews.

### Offline behaviour

The worker precaches the app shell (`/index.html`), the JS/CSS bundles, the
self-hosted fonts and the icons, and answers client-side routes through
`navigateFallback`. Article content ships inside the JS bundle, so every route
renders offline. The 19 prerendered HTML files are *not* precached: they are
written by `scripts/prerender.mjs` after `vite build`, which is when the service
worker has already been generated.

## Upstream template notes

This template provides a minimal setup to get React working in Vite with HMR and some Oxlint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## Expanding the Oxlint configuration

If you are developing a production application, we recommend using TypeScript with type-aware lint rules enabled. Check out the [TS template](https://github.com/vitejs/vite/tree/main/packages/create-vite/template-react-ts) for information on how to integrate TypeScript and Oxlint's TypeScript related rules in your project.
